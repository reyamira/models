# Models Tab

## Files
- `app.rs` — `ModelsApp` state, `Focus` (Models/Details), `ListMode` (Grouped/Offerings/Flat), `ModelGroup`, `SortOrder`, `Filters`, `ModelEntry`, provider-picker modal state, `detail_scroll: ScrollOffset`
- `render.rs` — `draw_main()` renders the 2-column layout (model list 60% | right panel 40%): `draw_grouped_list` (default), the flat/offerings renderer, the provider picker modal, group detail Providers section

## Key Patterns
- `ModelsApp::update_filtered_models(&mut self, providers)` takes `&[(String, Provider)]` param — providers live on `App`, not `ModelsApp`
- Column headers are **sticky** (a fixed line above the list, not item 0) — selection indices map 1:1 (`select(Some(idx))`, no +1)
- `ProviderListItem::CategoryHeader` items are non-selectable — `find_selectable_index()` skips them
- Sort/filter methods (`cycle_sort`, `toggle_reasoning`, etc.) live on `ModelsApp` and call `update_filtered_models` internally
- Detail panel uses `ScrollablePanel` widget with `detail_scroll: ScrollOffset` for scrollable, focus-aware rendering
- Focus toggles between Models ↔ Details (the provider sidebar is retired; `p` opens the provider modal)
- `reset_detail_scroll()` called on every model selection change (navigation, sort, filter, search)
- Provider modal rows display a category initial prefix (O/C/I/G/T for Origin/Cloud/Inference/Gateway/Tool); `provider_list_items` powers the modal, not a sidebar
- Grouped view state machine: `list_mode()` derives Grouped/Offerings/Flat from scope + `drill_key` + `flat_view`; `drill_name` is only the breadcrumb. Nav methods dispatch via `nav_len`/`nav_selected`/`nav_select`; canonical resolution uses `crate::labs` with the live `catalog.json` registry plus generated `data/models-dev-base-model-refs.json`. `set_lab_catalog` resolves a snapshot-wide identity map before search/filter/provider projection, so hiding a conflicting peer cannot change identity. Resolution is authoritative exact-ref → direct model id → provider/model id, then conservative anchor-backed canonical inference for leftovers, then a unique dual creator-qualified name + id lane for flattened namespaces, followed by exact-pair, one-sided creator, cross-record alias, and guarded complete-id alias reconciliation, and finally a canonical self-anchor lane. Those final lanes require one agreeing target, use only models.dev-authoritative seeds, never seed each other, and retain the creator/output blockers; the complete-id lane additionally rejects contradictory canonical or authoritative name evidence. The self-anchor lane is the exception on seeding — its leaf-id index comes solely from the canonical registry — and it therefore only fires where models.dev has never anchored that display name: the name must select one canonical record, the leaf id must equal that record's own leaf-id fingerprint (not membership in the alias-absorbing broad set), the leaf must be unique registry-wide, and no authoritative leaf-id or complete-id alias may point elsewhere. Collisions and unseen semantic suffixes fail closed. A final creator-prefixed-id lane mirrors the one-sided creator lane from the id side: its registry-only index keys each canonical record under `P(lab)` (lab slug + display-name fingerprints, each extended by one trailing `ai` token when its last token is not already `ai` — the pinned 581-key reading) followed by that record's own canonical leaf-id tokens, matched whole-token and order-sensitive; the leaf key is preferred, the complete-id key covers path-spelled namespaces, disagreeing leaf/complete keys are terminal, provider self-prefixes and junk prefixes produce no key at all, and the plain display name must independently select that same record (the barrier that refuses an undated id selecting a rolling record where models.dev links the dated snapshot). Remaining offerings peer-group sequentially on exact normalized name + leaf id, full id (flattened namespaces), then separator-compacted full id; each weaker lane sees only still-unlinked rows, and every whole multi-provider bucket must pass creator/output blockers. A final name-relaxation pass attaches a still-unlinked offering to an existing peer bucket that spells its exact leaf id when the bucket has an unambiguous lab and every name-token difference is creator attribution (lab slug/display tokens + `ai`; never family names), the offering's own id-namespace spelling, or a token the shared leaf id already carries — semantic tokens (dates, `preview`, `thinking`), ambiguous multi-bucket matches, and blocker conflicts refuse. `independent_lab` treats an unrecognized id-namespace prefix as attribution away from the provider (no provider-id fallback for `nvidia/qwen/…`-shaped ids). Per-offering provenance is retained; `≈` in grouped/provider/flat/drilled lists and the Identity detail row distinguish each canonical inference lane, peer identity, and models.dev-authored identity. Live `catalog.json` additions participate immediately, while new upstream TOML `base_model` edges require `mise run refresh-model-refs` and a binary release because the exact-ref artifact is pinned. `mise run audit-model-identity` runs provider-level held-out conformance plus live grouping/reconciliation distribution receipts, and a residual near-miss report (`live_residual_near_miss_report`) that enumerates the same-name/same-id seams and ranked fuzzy candidates among still-peer/unlinked rows — diagnostic only (fuzzy proposes for human/upstream disposition, never merges)

## Provider Detail Card
- Offerings/Flat modes only (grouped mode gives the detail panel the full height) — border always DarkGray (not focusable)
- Height dynamically computed from wrapped content lines + 2 borders
- Shows: provider name (Cyan+BOLD), category, docs URL, API URL, env var

## Gotchas
- Provider card border is intentionally always DarkGray — it's not in the focus cycle
- Headers are sticky widgets, not list items — never reintroduce the `idx + 1` header offset (it scrolls the header away permanently after `G`-then-`g`)
